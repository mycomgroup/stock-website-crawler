## 技术趋势树核心理念

技术树研究的是：**价格、成交量和趋势本身，是否能提供交易时点与行为信息**。

技术树最适合回答的问题，不是"这家公司值多少钱"，而是：

- **什么时候更适合买**
- **趋势是否开始**
- **资金是否开始共识**

你的任务是通过回测结果，找到有效的交易时点和趋势确认信号。

**技术树的定位：**

技术树最适合作为：
- 买点筛选器
- 卖点管理器
- 择时工具

它最不适合作为：
- 全部逻辑来源
- 长期基本面替代品

## E树的四个分支

### E1. 均线趋势

最经典的技术分支。

研究重点：
- 短中长期均线关系
- 均线角度
- 金叉、死叉、站上均线
- 回踩均线后的续涨概率

**自然语言条件样例（参考）：**

```
非ST，5日均线上穿20日均线，股价站上20日均线，20日均线向上

非ST，20日均线大于60日均线，60日均线大于120日均线，近10日涨跌幅从大到小排序

非ST，股价回踩20日均线后重新放量上涨，换手率大于2%
```

### E2. 缩量整理后突破

技术树里很有研究价值的一枝。

逻辑：
- 前期有上涨基础
- 随后量能收缩，筹码趋稳
- 再次放量时容易形成趋势延续

研究重点：
- 缩量阶段多长最好
- 放量的强度多少合适
- 哪些行业更适合这种形态

**自然语言条件样例（参考）：**

```
非ST，缩量上涨，涨跌幅小于7%，总市值从小到大排序

非ST，三连阳，近一日涨跌幅小于3%，成交量缩小

非ST，价升量缩，涨跌幅小于5%，近20日均线向上
```

### E3. MACD / BOLL / K线形态

这类指标适合作为辅助，不适合作为唯一逻辑。

你要研究的重点不是指标本身，而是：
- 指标在什么市场环境中有效
- 指标与基本面或资金面结合后是否提升胜率

**自然语言条件样例（参考）：**

```
非ST，MACD金叉，股价站上20日均线，近20日涨跌幅大于0

非ST，BOLL下轨反弹，近5日成交量放大，股价大于10日均线

非ST，下影线较长，换手率大于2%，总市值小于100亿元
```

### E4. 价格强度与相对强弱

研究的是：
- 最近20日、60日、120日谁更强
- 板块内谁强
- 市场整体谁强

它更适合作为排序因子，而不是单独策略。

**自然语言条件样例（参考）：**

```
非ST，近20日区间涨跌幅排名前20%，近60日区间涨跌幅大于0

非ST，股价大于120日均线，近10日涨跌幅从大到小排序前30

非ST，最近60日涨幅大于所属行业平均，回撤小于行业平均
```

## 技术树使用警示

在探索技术树时，要特别注意：

1. **不要把技术形态当成基本面替代品** - 技术信号是交易工具，不是选股逻辑
2. **技术指标在震荡市容易失效** - 关注趋势确认，避免频繁假信号
3. **单一技术指标胜率有限** - 需要结合其他条件或作为辅助确认
4. **注意过度拟合风险** - 技术参数容易过拟合历史数据

可以通过以下方式提升效果：
- 结合基本面条件（如盈利为正、估值合理）
- 结合资金面条件（如主力流入、股东户数下降）
- 结合成交量和换手率确认

### 第 4 步：执行迭代

```bash
SKILL_DIR="skills/autoresearch_10jqka_backtest"
python ${SKILL_DIR}/run_iteration.py \
    --base trees/E_technical_trend/experiments/<name> \
    --mutation-summary "【变异类型】具体改了什么（改前→改后），预期效果" \
    [--mutation-type <type>]
echo "exit: $?"
```

`--mutation-summary` 格式要求：
- 写清楚**变异类型**
- 写清楚**具体改了什么**
- 写清楚**预期效果**

`--mutation-type` 可选，不指定时系统随机选择变异类型。

**退出码含义：**
- `0` = keep（新配置更优，已保存为 champion）
- `1` = rollback（新配置不如 champion，已恢复）
- `2` = crash（执行出错，consecutive_failures +1）

## 回测参数探索

技术趋势策略的特点：

- **持仓周期**：通常较短，可探索 2-5 天
- **持仓数量**：**5-10支最佳**，技术信号股波动大需分散
- **止盈**：适中偏紧，可探索 12-25%
- **止损**：较紧，可探索 5-10%
- **移动止损**：技术策略特别需要，保护利润

根据回测结果调整：
- 如果选股太少（<3支） → 放宽技术条件或减少筛选
- 如果选股太多（>15支） → 加强趋势确认条件
- 如果回撤太大 → 收紧止损或添加基本面过滤
- 如果收益太低 → 尝试不同的技术分支或调整持仓周期

## 每次迭代要回答的标准问题

在每次变异前，问自己这几个问题：

### 逻辑问题
- 这个改动捕捉的是什么信号？趋势启动、趋势确认，还是趋势延续？
- 这个技术信号依赖什么市场环境？

### 因子问题
- 主因子是什么？辅因子是什么？
- 哪些因子是确认趋势的？哪些是控制风险的？

### 市场环境问题
- 趋势市场更有效还是震荡市场更有效？
- 流动性收缩时信号是否会失效？

### 风险问题
- 最大回撤可能来自什么？（假突破、趋势反转）
- 失效时会怎么失效？是连续小亏，还是单次大亏？

## 技术树研究常见错误（避坑）

1. **把技术形态当成基本面替代品** - 技术信号只是择时工具
2. **过度优化技术参数** - 容易过拟合历史数据
3. **忽略市场环境** - 技术信号在震荡市容易失效
4. **单一指标决策** - 应结合多个确认信号
5. **没有风控措施** - 技术策略必须有止损机制

## 评分公式（v2 - 防过拟合优化版）

```
calmar = annual_return / max(abs(max_drawdown), 0.01)
complexity_penalty = min((formula条件数 + 调优参数数) / 10, 1.0)

# 选股数量惩罚（双边软约束）
if maxPositions < 5:
    position_penalty = (5 - maxPositions) ** 2 * 0.1  # 选1支扣1.6分
elif maxPositions > 15:
    position_penalty = (maxPositions - 15) ** 2 * 0.01  # 选50支扣1.2分
else:
    position_penalty = 0

score = sortino * 0.40 + calmar * 0.25 + information_ratio * 0.15 
      + win_rate * 0.10 - complexity_penalty * 0.10 - position_penalty
```

**选股数量建议**：5-10支最佳，避免过拟合。

**硬约束**：
- `abs(max_drawdown) > 0.35` 直接 rollback
- 新 score **严格大于** champion score 才 keep

## 简洁性原则

改动要权衡收益和复杂度：
- 微小提升（score 提升 < 0.001）但增加了大量复杂配置 → **不值得**
- 删掉筛选条件后得分持平或更好 → **一定 keep**
- 得分接近但配置更简洁 → **keep**
