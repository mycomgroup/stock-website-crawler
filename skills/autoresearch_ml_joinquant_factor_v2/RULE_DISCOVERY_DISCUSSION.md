# 规则挖掘与策略优化：从经验到系统化

**日期**: 2026年4月21日  
**背景**: ML模型优化研究遇到瓶颈，简单经验规则表现更优

---

## 一、核心问题分析

### 1.1 当前困境

经过5轮系统性测试，我们发现了一个令人深思的现象：

| 方法 | 年化收益 | 提升来源 |
|------|---------|---------|
| **ML模型优化** (Phase 1→Phase 2) | +0.15pp | 2年额外训练数据 |
| **简单规则过滤** (EPS>0.5) | +25.87pp | 经验规则 |

**关键发现**：
- ❌ ML模型的预测值在Top 50股票中几乎无区分度（差异仅0.0003）
- ✅ 简单的EPS过滤规则带来了170倍于模型优化的收益提升
- ⚠️ "做了一大堆还不如我的经验好使"

### 1.2 深层原因

#### 为什么经验规则更有效？

**1. 因果关系 vs 相关关系**

```
经验规则（EPS>0.5）：
  - 直接反映公司盈利能力
  - 因果链清晰：盈利→现金流→持续经营→股价支撑
  - 稳定性高：盈利能力是基本面，不易被操纵

ML模型（260+因子）：
  - 学习历史相关性
  - 因果链模糊：因子A高→收益好（但为什么？）
  - 稳定性差：相关性可能随市场环境变化
```

**2. 信噪比问题**

```
经验规则：
  - 信号强度：高（直接指向盈利质量）
  - 噪音水平：低（财务数据相对可靠）
  - 信噪比：高

ML模型：
  - 信号强度：弱（260+因子中大部分是噪音）
  - 噪音水平：高（技术指标、市场情绪等易受干扰）
  - 信噪比：低
```

**3. 可解释性与信任度**

```
经验规则：
  - "只选盈利公司" → 投资者能理解并信任
  - 逻辑透明，易于调整和改进
  - 符合投资常识

ML模型：
  - "因子X权重0.023" → 黑盒，难以理解
  - 逻辑不透明，难以诊断问题
  - 可能学到虚假模式
```

### 1.3 模型的真正问题

从`validate_predictability.py`的结果看：

```
事后Top 20的平均预测值: 0.5234
事后Bottom 30的平均预测值: 0.5231
预测值差异: 0.0003

结论：模型在Top 50内部几乎没有区分能力
```

**这说明什么？**

1. **模型学到的是"噪音"而非"模式"**
   - 260+因子中大部分是市场噪音
   - 模型拟合了历史偶然性，而非本质规律

2. **过度拟合历史数据**
   - 在训练集上表现好，但泛化能力差
   - 预测值高度集中，失去区分度

3. **缺少"硬约束"**
   - 模型可以选择任何股票，包括亏损公司
   - 没有基本面质量的底线要求

## 二、10jqka_backtest框架的启示

### 2.1 框架核心思想

10jqka_backtest系统采用了一种**规则进化**的方法：

```
1. 种子策略库（67个）
   ├─ A树：价值规则（低PE、高股息等）
   ├─ B树：质量成长规则（高ROE、高增长等）
   ├─ C树：小盘规则（小市值+低估值等）
   └─ ...

2. 变异引擎
   ├─ 调整阈值：PE<30 → PE<25
   ├─ 添加条件：+ "毛利率>30%"
   ├─ 移除条件：- "换手率>5%"
   └─ 替换条件：市值排序 → 换手率排序

3. 自适应学习
   ├─ UCB1算法选择变异类型
   ├─ 记录每种变异的效果
   └─ 优先尝试历史表现好的变异

4. Git版本管理
   ├─ 每次改进自动commit
   ├─ 失败自动rollback
   └─ 可追溯完整演化历史
```

### 2.2 关键设计特点

#### 特点1：规则可解释

```json
{
  "name": "PEG低估值高增长策略",
  "formula": [
    "非ST",
    "PEG小于1",
    "净利润同比增长率大于30%",
    "营收同比增长率大于20%"
  ]
}
```

每个条件都有明确的投资逻辑：
- PEG<1：估值合理
- 净利润增长>30%：高成长
- 营收增长>20%：增长质量高

#### 特点2：模块化组合

```
基础池过滤：非ST + 流动性要求
    ↓
质量筛选：ROE、毛利率、现金流
    ↓
估值筛选：PE、PB、PEG
    ↓
排序选股：按某个指标排序取Top N
```

每个模块独立，可以灵活组合和替换。

#### 特点3：渐进式优化

```
初始策略（Baseline）
    ↓
变异1：调整PE阈值 30→25 → 提升2%
    ↓
变异2：添加毛利率>30% → 提升3%
    ↓
变异3：调整持仓数 5→8 → 提升1%
    ↓
...
```

每次只改一个参数，清楚知道每个改动的贡献。

#### 特点4：自动化探索

- **不需要人工猜测**：系统自动尝试各种组合
- **智能选择方向**：UCB1算法平衡探索与利用
- **持续学习**：记录历史表现，优化搜索策略

## 三、两种方法的对比

### 3.1 方法论对比

| 维度 | ML因子模型 | 规则进化系统 |
|------|-----------|-------------|
| **核心思想** | 学习历史相关性 | 编码投资逻辑 |
| **输入** | 260+个因子 | 可解释的规则 |

| **泛化能力** | 易过拟合 | 逻辑稳定 |

### 3.2 实际效果对比

**当前研究结果**：

```
ML模型（Phase 2）：
  - 训练数据：2015-2025（10年）
  - 因子数量：260+
  - 2026年收益：-1.10%

  - 规则数量：1个

  - 2026年收益：24.77%
  - 提升幅度：+25.87pp
```

**为什么会这样？**

1. **ML模型的问题**：
   - 学到了太多噪音（260+因子中大部分无效）
   - 过度拟合历史数据
   - 缺少基本面约束

2. **规则的优势**：
   - 直接编码投资逻辑（盈利能力）
   - 因果关系清晰
   - 不受历史噪音干扰

## 四、融合方案设计

### 4.1 核心思路

**不是"ML vs 规则"，而是"ML + 规则"**

```
第一层：规则过滤（硬约束）
  ├─ 基础质量：非ST、流动性、盈利能力
  ├─ 财务健康：现金流、负债率、应收账款
  └─ 估值合理：PE、PB、PEG范围

第二层：ML排序（软排序）
  ├─ 在高质量池中使用ML模型
  ├─ 预测相对强弱
  └─ 选择Top N

第三层：规则优化（自动进化）
  ├─ 系统化测试规则组合
  ├─ 自动发现有效规则
  └─ 持续优化参数
```

### 4.2 具体实施方案

#### 方案A：规则库 + ML排序

```python
# 伪代码示例
def select_stocks(date, ml_model, rule_config):
    # 第一阶段：规则过滤
    candidates = apply_rules(
        date=date,
        rules=[
            "非ST",
            "EPS > 0.5",
            "流通市值 > 10亿",
            "ROE > 10%",
            "资产负债率 < 70%"
        ]
    )
    
    # 第二阶段：ML排序
    predictions = ml_model.predict(candidates)
    top_stocks = predictions.nlargest(50, 'prediction')
    
    return top_stocks
```

**优势**：
- 规则保证基本面质量
- ML在高质量池中发挥作用
- 结合两者优势

#### 方案B：规则进化 + ML验证

```python
# 伪代码示例
def evolve_rules(initial_rules, ml_model):
    best_rules = initial_rules
    best_score = evaluate(best_rules, ml_model)
    
    for iteration in range(100):
        # 变异规则
        new_rules = mutate(best_rules)
        
        # ML模型验证
        new_score = evaluate(new_rules, ml_model)
        
        # 保留更好的规则
        if new_score > best_score:
            best_rules = new_rules
            best_score = new_score
    
    return best_rules
```

**优势**：
- 自动发现有效规则组合
- ML模型作为评估器
- 持续优化

#### 方案C：分层规则系统

```
Layer 1: 基础过滤（必须满足）
  - 非ST、非退市
  - 流动性要求
  - 数据完整性

Layer 2: 质量筛选（可配置）
  - 盈利能力：EPS、ROE、毛利率
  - 成长性：营收增长、利润增长
  - 财务健康：现金流、负债率

Layer 3: 估值筛选（可配置）
  - PE、PB、PS范围
  - PEG < 某阈值
  - 股息率 > 某阈值

Layer 4: ML排序（软排序）
  - 在通过前3层的股票中
  - 使用ML模型预测
  - 选择Top N
```

### 4.3 规则发现流程

借鉴10jqka_backtest的方法：

```
1. 初始化种子规则库
   ├─ 从现有经验提取（如EPS>0.5）
   ├─ 从10jqka种子库借鉴
   └─ 从投资理论推导

2. 批量测试种子规则
   ├─ 在2015-2025历史数据上回测
   ├─ 记录每个规则的效果
   └─ 筛选出Top 20规则

3. 规则组合优化
   ├─ 测试规则的组合效果
   ├─ 发现协同作用
   └─ 避免冗余规则

4. 参数自动调优
   ├─ 对每个规则的阈值进行优化
   ├─ 使用网格搜索或贝叶斯优化
   └─ 交叉验证避免过拟合

5. 持续进化
   ├─ 定期在新数据上验证
   ├─ 淘汰失效规则
   └─ 添加新规则
```

## 六、关键问题与讨论

### 6.1 如何避免规则过拟合？

**问题**：规则也可能过拟合历史数据

**解决方案**：
1. **交叉验证**
   - 在多个时间段测试
   - 确保规则在不同市场环境下有效

2. **逻辑验证**
   - 每个规则必须有投资逻辑支撑
   - 不能只因为"历史有效"就采用

3. **简单性原则**
   - 优先选择简单规则
   - 避免过于复杂的组合

4. **样本外测试**
   - 保留最新数据作为测试集
   - 规则在测试集上也要有效

### 6.2 规则库如何维护？

**问题**：规则可能随时间失效

**解决方案**：
1. **定期验证**
   - 每季度在新数据上测试
   - 淘汰失效规则

2. **版本管理**
   - 使用Git管理规则库
   - 记录每个规则的历史表现

3. **A/B测试**
   - 新规则先小规模测试
   - 验证后再全面应用

4. **规则分级**
   ```
   核心规则（必须满足）：
   - 非ST、流动性、盈利能力
   
   可选规则（可配置）：
   - 估值、成长、质量指标
   
   实验规则（待验证）：
   - 新发现的规则
   ```

### 6.3 如何平衡规则与ML？

**问题**：规则太严可能错失机会，太松则无效

**解决方案**：
1. **分层设计**
   ```
   硬约束（规则）：保证基本面质量
   软排序（ML）：在高质量池中选优
   ```

2. **动态调整**
   ```
   根据市场环境调整规则严格度：
   - 牛市：放松规则，增加持仓
   - 熊市：收紧规则，提高质量
   ```

3. **效果归因**
   ```
   分别统计：
   - 规则过滤的贡献
   - ML排序的贡献
   - 两者协同的贡献
   ```

### 6.4 计算效率如何保证？

**问题**：批量测试规则组合计算量大

**解决方案**：
1. **增量计算**
   - 缓存中间结果
   - 只重新计算变化部分

2. **并行化**
   - 多进程测试不同规则
   - GPU加速因子计算

3. **智能剪枝**
   - 提前终止明显无效的规则
   - 优先测试有潜力的组合

4. **采样测试**
   - 先在小样本上快速测试
   - 有效规则再全量测试

## 九、总结

### 9.1 核心洞察

1. **简单规则 > 复杂模型**
   - EPS>0.5（1个规则）带来25.87pp提升
   - Phase 1→Phase 2（2年数据）仅带来0.15pp提升
   - 比例：170:1

2. **因果逻辑 > 历史相关**
   - 规则编码投资逻辑（盈利能力→股价支撑）
   - ML学习历史相关（因子A高→收益好）
   - 规则更稳定、可解释

3. **系统化 > 临时拍脑袋**
   - 10jqka框架：67个种子 + 自动进化
   - 当前方法：手工尝试 + 运气
   - 需要将"经验"转化为"流水线"

### 9.2 行动方向

**不是放弃ML，而是重新定位ML的角色**：

```
旧模式：
  ML模型 → 直接选股 → 效果差

新模式：
  规则过滤（硬约束）→ ML排序（软排序）→ 效果好
```

**不是手工试规则，而是系统化发现规则**：

```
旧模式：
  拍脑袋想规则 → 手工测试 → 效率低

新模式：
  种子规则库 → 自动变异 → 自适应学习 → 效率高
```
