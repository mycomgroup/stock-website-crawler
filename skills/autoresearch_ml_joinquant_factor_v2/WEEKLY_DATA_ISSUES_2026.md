# 2026年周数据问题总结

## 问题发现
下载2026年1月-4月的周数据时，发现以下日期的pchg计算异常：

| 日期 | 原始问题 | 根本原因 |
|------|---------|---------|
| 20260202 | 所有pchg = -1.0 | 下周(2026-02-13)价格全为0 |
| 20260223 | 所有pchg = nan | 本周(2026-02-27)价格全为0 |
| 20260302 | 所有pchg = inf | 本周(2026-03-06)价格全为0 |

## 根本原因
DuckDB数据库(`/Users/yuping/Downloads/git/timesfm-cn-forecast-clean/data/market.duckdb`)中以下日期的价格数据异常：

```
2026-02-06: 5208条记录, 其中2065条价格=0 (39.6%)
2026-02-13: 5179条记录, 全部价格=0 (100%) ⚠️
2026-02-27: 5174条记录, 全部价格=0 (100%) ⚠️
2026-03-06: 5177条记录, 5174条价格=0 (99.9%) ⚠️
```

**这是上游数据源的问题，不是下载脚本的问题。**

## 解决方案

### 1. 脚本修复（已完成）
修改了`download_factors_with_price.py`中的pchg计算逻辑：

```python
def calc_pchg(row):
    p1 = row['price_this_week']
    p2 = row['price_next_week']
    # 如果任一价格为None、0或负数，返回None
    if p1 is None or p2 is None or p1 <= 0 or p2 <= 0:
        return None
    return (p2 / p1) - 1
```

**效果：**
- ✅ 避免了除以0导致的inf错误
- ✅ 避免了价格为0导致的-1.0错误
- ✅ 对于无效价格，统一返回nan

### 2. 数据使用建议
在后续分析中应该：

1. **过滤掉pchg全为nan的周**
   ```python
   # 检查每个文件的有效pchg比例
   valid_ratio = df['pchg'].notna().sum() / len(df)
   if valid_ratio < 0.5:  # 如果有效数据少于50%
       print(f"跳过 {filename}: 有效pchg仅{valid_ratio:.1%}")
       continue
   ```

2. **或者等待数据源修复后重新下载**
   - 联系DuckDB数据维护者
   - 检查原始数据源是否有问题
   - 重新运行数据更新流程
