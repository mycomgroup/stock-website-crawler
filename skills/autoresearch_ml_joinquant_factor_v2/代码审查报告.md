# `autoresearch_ml_joinquant_factor_v2` 代码总结与审查

## 一、项目概览

这是一个 **A 股弱因子合成量化策略** 项目，基于聚宽（JoinQuant）的 260 个因子数据，实现了一套从因子清洗到组合构建的完整 pipeline。

### 项目结构

```
autoresearch_ml_joinquant_factor_v2/
├── 弱因子组合量化策略技术方案.md        # 技术方案文档（1495行，非常详细）
├── weak_factor_portfolio.py            # v1 旧版实现（已废弃）
├── step1-挖新的指标 加上时间窗口的回测.ipynb  # 探索性 notebook
└── v2/                                 # v2 重构实现
    ├── pipeline.py                     # 完整 pipeline 集成
    ├── run_phase1.py                   # Phase 1 端到端验证
    ├── generate_test_data.py           # 测试数据生成
    ├── data/
    │   └── pit_panel.py               # L0：点时一致数据面板（1035行）
    ├── preprocessing/
    │   └── factor_preprocessor.py     # L1：去极值/填补/标准化/中性化（773行）
    ├── family/
    │   ├── family_map.py              # L2：9 家族映射（260 因子）
    │   └── redundancy.py             # L2：冗余检测与准入管理
    ├── synthesis/
    │   ├── intra_family.py           # L3：组内合成（等权/ridge/PC1/stacking）
    │   ├── cross_family.py           # L4：组间收缩合成（ridge/elastic net）
    │   ├── residual_overlay.py       # L5：GBDT 残差增强（Phase 2）
    │   ├── regime_overlay.py         # L6：软性 regime 调节（Phase 2）
    │   └── horizon_calibration.py    # Horizon 校准（Phase 2）
    ├── portfolio/
    │   ├── optimizer.py              # L7：Top-N 等权优化器
    │   └── qp_optimizer.py           # L7：QP 二次规划优化器（Phase 2）
    ├── evaluation/
    │   ├── metrics.py                # 评估指标（IC/ICIR/Sharpe/上线闸门）
    │   ├── bootstrap.py              # Bootstrap 统计检验
    │   ├── capacity.py               # 容量测试
    │   └── freshness.py              # 因子新鲜度评估
    ├── validation/
    │   └── walk_forward.py           # OOF Walk-Forward 验证框架
    ├── results/
    │   └── persistence.py            # 结果持久化
    └── tests/                         # 测试文件（每个模块都有对应测试）
```

### 核心架构：8 层 Pipeline

```
L0 数据治理（PIT 一致性）→ L1 因子预处理 → L2 家族划分 → L3 组内合成 →
L4 组间收缩合成 → L5 残差增强（Phase 2）→ L6 Regime Overlay（Phase 2）→
L7 组合优化
```

## 二、各层详细分析

### L0：数据治理 — [pit_panel.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/data/pit_panel.py)

**实现内容**：
- CSV 加载与列重命名（`Unnamed: 0` → `stock_id`）
- 可交易掩码（ST/停牌/涨跌停一字板/新股冷启动/退市整理）
- 财务因子时滞校验（按披露日 `ann_date` 置 NaN 防止未来信息泄漏）
- 存活偏差检查（识别潜在退市股票，IC 对比分析）

**设计亮点**：字段缺失时优雅退化（跳过对应过滤 + 日志警告），不会因缺少辅助列而报错。

### L1：因子预处理 — [factor_preprocessor.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/preprocessing/factor_preprocessor.py)

**实现内容**：
- 去极值：按日截面 `median ± 5×MAD`（向量化实现）
- 缺失填补：财务类 → 截面中位数，微观结构类 → 按股票前推
- 双轨标准化：rank 表示 + robust zscore 并行输出
- 风格中性化：WLS + ridge 横截面回归残差化（行业哑变量 + 连续暴露）

**设计亮点**：严格按日截面独立操作，禁止全局统计量；向量化实现性能好。

### L2：家族划分 — [family_map.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/family/family_map.py) + [redundancy.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/family/redundancy.py)

**实现内容**：
- 9 个经济家族的冻结映射（260 个因子）
- 自动去重（跨家族重复因子保留首次出现）
- 有效维度计算 `n_eff = (Σλ)² / Σλ²`
- 冗余因子对检测（截面 rank 相关 > 0.8）
- 三段式准入管理（影子池 → 观察期 → 正式/淘汰）

### L3：组内合成 — [intra_family.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/synthesis/intra_family.py)

**实现内容**：
- 等权 rank 平均（`equal_rank_score`，基线）
- Rolling ridge OOF 预测（`ridge_family_score`）
- PC1 + 符号锚定 + 不稳定检测（`pc1_score_with_sign_anchor`）
- 非负 ridge stacking（`stack_family_scores_oof`）

### L4：组间收缩合成 — [cross_family.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/synthesis/cross_family.py)

**实现内容**：
- Ridge / Elastic Net 回归合成家族分数
- 单家族权重上限（0.4）
- 指数平滑 beta 权重
- Inner loop 超参选择（grid search + validation split）

### L7：组合优化 — [optimizer.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/portfolio/optimizer.py) + [qp_optimizer.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/portfolio/qp_optimizer.py)

**实现内容**：
- Top-N 等权优化器（Phase 1 默认）：单票上限、换手约束、不可交易冻结
- QP 二次规划优化器（Phase 2）：风险惩罚 + 换手成本 + 集中度惩罚 + 行业约束

## 三、发现的问题

### 🔴 严重问题

#### 1. `family_map.py` 存在跨家族重复因子

```python
# style 家族中的 "market_leverage" 与 quality 家族中的同名因子重复
# 虽然 _deduplicate_family_map() 会去重，但这意味着声称的 260 个因子不准确
```

实际检查发现 `market_leverage` 同时出现在 `quality`（line 219）和 `style`（line 289）中。去重后 style 家族实际只有 29 个因子，不是文档声称的 30 个。

> [!WARNING]
> 建议手动审计全部 260 个因子的归属，确认无遗漏/错放。

#### 2. `pipeline.py` 中 L7 循环效率极低

[pipeline.py:247-264](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/pipeline.py#L247-L264) 中逐日循环调用 `optimizer.optimize()`，并且每次都做 `self.panel.df[self.panel.df["date"] == date]` 的全表过滤：

```python
for date in sorted(alpha_linear.index.get_level_values("date").unique()):
    date_alpha = alpha_linear.xs(date, level="date")
    date_tradable = self.panel.tradable_mask[
        self.panel.df["date"] == date          # ← 每次全表扫描
    ]
```

对 800+ 周 × 80 万行数据，这会极慢。

#### 3. `impute_factors` 的 forward fill 存在 O(n²) 潜在性能问题

[factor_preprocessor.py:295-305](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/preprocessing/factor_preprocessor.py#L295-L305) 中的 forward fill 实现用了嵌套循环：

```python
for i in range(len(col)):
    if mask_nan[i]:
        prev = idx[idx < i]           # ← 每个 NaN 都做一次数组比较
        if len(prev) > 0:
            col[i] = col[prev[-1]]
```

应该用 `pd.Series.ffill()` 或维护 `last_valid` 指针。

#### 4. `weak_factor_portfolio.py` (v1) 有两个同名 `signal_equal_weighted` 方法

[weak_factor_portfolio.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/weak_factor_portfolio.py) 在 line 615 和 line 688 定义了两个 `signal_equal_weighted` 方法，后者覆盖前者。虽然 v1 已废弃，但如果有代码引用了 v1 的这个方法，行为可能不符合预期。

### 🟡 中等问题

#### 5. `standardize_factors` 在循环内重复 import

[factor_preprocessor.py:459](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/preprocessing/factor_preprocessor.py#L459) 在每个日期截面的循环内做 `from scipy.stats import rankdata`：

```python
for d in np.unique(date_codes):
    ...
    from scipy.stats import rankdata  # ← 应提到函数外部
```

虽然 Python 会缓存 import，但这是不良实践。

#### 6. `CrossFamilyModel.fit()` 有 `fillna(0)` 对标签的不当处理

[cross_family.py:106](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/synthesis/cross_family.py#L106)：

```python
y = y_train.loc[common_idx].fillna(0).values  # ← 标签缺失直接填 0
```

将缺失的收益标签填为 0 会引入偏差（尤其在牛/熊市），应该移除 NaN 行而非填零。

#### 7. Pipeline 固定使用 70/30 train/test split，未用 walk-forward

[pipeline.py:222-224](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/pipeline.py#L222-L224)：

```python

train_dates = dates[:split_idx]
test_dates = dates[split_idx:]
```

`pipeline.py` 注释说"For Phase 1"，但已经有完整的 `WalkForwardSplitter`，主 pipeline 却没有用。

#### 8. `run_phase1.py` 中 OOF 预测字典可能丢失后期 fold 的数据

[run_phase1.py:218-219](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/run_phase1.py#L218-L219)：

```python
for key, val in preds.items():
    if key not in oof_preds:   # ← 保留最早 fold 的预测，丢弃后续 fold 的
        oof_preds[key] = val
```

walk-forward 中同一个 `(date, stock)` 可能出现在多个 fold 的 test block 中。当前实现保留最早的预测（训练数据最少的 fold），通常应该保留**最新的**（训练数据最多的）。

#### 9. `pc1_score_with_sign_anchor` 对 `anchor_score.get()` 的调用不安全

[intra_family.py:273-276](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/synthesis/intra_family.py#L273-L276)：

```python
if hasattr(anchor_score, "get"):
    eq_val = anchor_score.get(key, 0.0)    # ← pd.Series.get 在某些版本有问题
elif key in anchor_score.index:
    eq_val = float(anchor_score[key])
```

`pd.Series` 有 `.get()` 方法但行为与 dict 不完全一致（尤其是 MultiIndex 场景）。

#### 10. L1 中性化 `neutralize_factors` 未在主 pipeline 中调用

[pipeline.py](file:///Users/fengzhi/Downloads/git/testlixingren/skills/autoresearch_ml_joinquant_factor_v2/v2/pipeline.py) 的 L1 步骤只做了 winsor → impute → standardize，对技术方案中强调的风格中性化（6.5 节）跳过了。对于追求纯 alpha 合成的场景，这是一个重要遗漏。

## 四、改进建议

### 高优先级

| # | 建议 | 影响 |
|---|------|------|
| 1 | **修复 OOF 预测保留策略**：`run_phase1.py` 中应保留最新 fold 的预测（训练数据最多），而非最早的 | 影响回测 IC 评估准确性 |
| 2 | **标签 fillna(0) 改为 dropna**：`CrossFamilyModel.fit()` 中不应对标签填零 | 影响模型训练质量 |
| 3 | **pipeline.py 接入 WalkForwardSplitter**：主 pipeline 应使用 walk-forward OOF 而非简单 split | 影响回测可信度 |
| 4 | **优化 L7 循环**：对 tradable_mask 预先按日期建索引（`groupby("date")` → dict），避免逐日全表扫描 | 性能提升 10-100x |

### 中优先级

| # | 建议 | 影响 |
|---|------|------|
| 5 | **补全 L1 中性化步骤**：在 pipeline 中调用 `neutralize_factors`，至少中性化行业和市值 | 降低风格暴露残留 |
| 6 | **修复 forward fill 性能**：用 `pd.DataFrame.ffill()` 替代手动嵌套循环 | 大数据集性能 |
| 7 | **审核 family_map 因子计数**：修复 `market_leverage` 重复、`technical` 计数不一致 | 数据完整性 |
| 8 | **将 import 提到函数顶部**：`scipy.stats.rankdata` 应在模块级导入 | 代码规范 |

### 低优先级

| # | 建议 | 影响 |
|---|------|------|
| 9 | **增加 data contract 验证层**：在 pipeline 各层之间增加 schema 校验（列名、类型、NaN 比例） | 调试效率 |
| 10 | **为 Phase 2 模块补齐实现**：特别是 `neutralize_factors` 的行业数据准备、`QPOptimizer` 的行业约束 | 功能完整性 |
| 11 | **删除或隔离 v1 代码**：`weak_factor_portfolio.py` 已废弃但仍留在目录中，容易混淆 | 代码整洁 |
| 12 | **增加 pipeline 中间状态持久化**：每层输出保存 parquet，便于断点续跑和调试 | 开发效率 |

## 五、总体评价

### 优点

1. **技术方案极其详尽**：1500 行的技术文档覆盖了从理论到实现的完整链路，是高质量的量化研究文档
2. **分层架构清晰**：L0-L7 的 8 层设计严格分离了数据治理、因子合成和组合构建
3. **OOF 意识强**：全程强调 OOF 验证，walk-forward + embargo + final holdout 三重防线
4. **测试覆盖好**：每个核心模块都有独立的测试文件
5. **数值实现扎实**：预处理的向量化实现、ridge 回归的正规方程求解、PC1 的符号锚定都写得很好
6. **防过拟合设计**：收缩法为主线、非线性只做残差增强、eta=0 始终保留合法

### 不足

1. **Phase 2 功能大量 stub**：中性化未接入 pipeline、regime overlay / horizon calibration 停留在占位
2. **主 pipeline 与验证脚本不一致**：`pipeline.py` 用简单 split，`run_phase1.py` 手写 walk-forward
3. **性能瓶颈**：几处 O(n²) 循环和全表扫描在实际数据规模（61 万行）下会很慢
4. **缺少风险模型**：L7 的 `QPOptimizer` 默认用单位矩阵作为协方差，技术方案中强调的 Barra/CNE6 完全未实现
5. **缺少实盘对接层**：只有回测框架，没有信号发出、下单执行模块
