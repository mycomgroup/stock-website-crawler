# 股票弱因子合成技术方案

**版本：** v2.0  
**定位：** A 股股票横截面弱因子合成的终极方案  
**适用场景：** 100～500 个弱因子，周频或月频选股，长多头或市场中性  
**文档目标：** 给出一套更成熟、可生产、可扩展、可验证的因子合成总设计

---

## 一、先把问题定义对

这类课题的第一原则，不是“怎么把很多因子加起来”，而是先把三个层次彻底分开：

1. **因子层**：单个原始因子如何清洗、标准化、去风格、评估增量信息。
2. **合成层**：如何把多个弱因子合成一个更稳定的 `alpha score`。
3. **组合层**：如何把 `alpha score` 转成真实持仓，并考虑风险、成本、容量、执行。

这三层如果混写，回测很容易好看，实盘却很难定位问题。

本方案明确规定：

- **因子合成层的输出** 是每个再平衡日、每只股票的预测分数 `s_{t,i}`。
- **组合构建层的输出** 才是组合权重 `w_{t,i}`。
- 止损、波动率目标、单票约束、行业约束、换手约束都属于**组合层**，不属于因子合成层。

---

## 二、最终推荐路线

如果目标是“一次性把设计拉到比较高的成熟度”，默认推荐主线不是：

- 200 个因子直接等权
- 200 个因子直接喂 LightGBM
- 三路信号固定 `40/30/30`
- 最近 63 天 IC 排名前 70 的因子直接激活

而是：

## **分层收缩合成 + OOF 叠加 + 成本感知组合优化**

英文可记为：

## **Hierarchical Shrinkage Ensemble with Optimizer-Aware Alpha**

其核心思想是：

1. 先按经济含义和统计相关性把因子分成若干家族。
2. 先做**组内合成**，再做**组间合成**，避免相似因子重复刷权重。
3. 合成时默认用**收缩法**，而不是“近期谁好就重仓谁”。
4. 非线性模型只做**残差增强**，不做全权主模型。
5. 真正的风险和成本约束放进**组合优化器**，而不是在因子分数上硬止损。

这条路线比“多路信号拍脑袋加权”成熟得多，也更符合高维资产定价和实盘量化的经验。

---

## 三、成熟方案背后的共识

这个 topic 的成熟经验，归纳下来就是下面 8 条：

1. **高维弱因子合成的第一武器是收缩，不是复杂模型。**
2. **因子之间高度相关，名义因子数远大于有效维度。**
3. **组内先降冗余，组间再叠加，通常优于“一锅炖”。**
4. **OOF 预测比样本内指标更重要。**
5. **交易成本、换手和容量会吃掉大量纸面 alpha。**
6. **手工牛熊分段通常带有 hindsight bias，只适合做辅助分析。**
7. **非线性是有价值的，但更适合作为线性主模型的 residual overlay。**
8. **最终表现往往由数据时点正确性和组合约束决定，而不是多一个 fancy 模型。**

---

## 四、终极架构总览

```text
L0 数据治理与点时一致性
   ↓
L1 因子预处理
   - 去极值 / 缺失处理 / 截面标准化 / 风格中性化
   ↓
L2 因子家族划分与冗余压缩
   - 经济分类 + 相关聚类 + 有效维度评估
   ↓
L3 组内合成
   - rank blend / ridge / PC1 / PLS
   ↓
L4 组间收缩合成（主模型）
   - rolling ridge / elastic net / Bayesian shrinkage
   ↓
L5 非线性残差增强（可选）
   - GBDT / shallow NN，仅做 residual alpha
   ↓
L6 软性 regime overlay（可选）
   - 只做轻量调节，不做手工硬切换
   ↓
L7 成本感知组合优化
   - 风险模型 + 成本模型 + 约束优化
   ↓
L8 执行、监控与样本外验证
```

这 8 层里，真正决定方案成熟度的通常是 `L0/L1/L4/L7/L8`。

## 五、数据契约与点时一致性

### 5.1 输入张量定义

建议统一使用下面的数据结构：

- `X[t, i, k]`：在日期 `t` 可观测到的，第 `i` 只股票、第 `k` 个因子值
- `y[t+1, i]`：从 `t` 到下一次再平衡日的未来收益或超额收益
- `B[t, i, m]`：风险暴露，如行业、对数市值、beta、残差波动、流动性
- `tradable[t, i]`：日期 `t` 是否可交易
- `cost[t, i]`：交易成本估计
- `risk_cov[t]`：组合优化所需风险协方差或 Barra 风险模型输出

### 5.2 标签定义

默认推荐：

- 若做**月频选股**，标签定义为下一个月的**超额收益**或**行业/风格中性后的残差收益**。
- 若做**周频选股**，标签定义为下一周的超额收益。

不要默认直接预测原始收益，因为很多“有效因子”其实只是大小盘、行业、beta 暴露。

### 5.3 A 股必须遵守的点时规则

- 成分股必须使用**当时可得股票池**，不能用当前成分回溯。
- 财务因子必须按**实际披露日**生效，不能按报告期末提前生效。
- 对停牌、涨跌停、一字板、ST、退市整理、新股冷启动都要有明确过滤规则。
- 复权价格、总股本、流通股本、行业分类都必须是 point-in-time。
- 任何“用全样本均值/标准差/缺失分布”做预处理的步骤都要禁止。

### 5.4 因子衰减速度与标签周期必须对齐

不同因子的有效周期并不相同，不能假设所有因子都天然适配同一个标签周期。

建议把因子按衰减速度粗分为三类：

- **快衰减因子**：微观结构、短期反转、盘口和事件驱动，典型标签 `1w ~ 2w`
- **中速因子**：中期动量、分析师修正、部分行为因子，典型标签 `1m`
- **慢速因子**：价值、质量、成长、资本结构，典型标签 `3m` 甚至更长

本方案需要明确区分两个 horizon：

- **native horizon `h_g`**：某个家族最擅长预测的自然期限
- **decision horizon `h*`**：组合层真正做优化和持有决策的统一期限

成熟做法不是直接把不同 horizon 的分数丢进同一个 L4，而是：

1. 每个家族先在最合适的 native horizon 上训练，得到 OOF 分数 `s_g^{(h_g)}`
2. 再用**仅基于 OOF 样本**的校准器，把 `s_g^{(h_g)}` 映射成对统一 decision horizon `h*` 的预测
3. 只有校准后的分数 `\tilde{s}_g^{(h*)}` 才允许进入 L4

推荐的默认映射形式：

```text
\tilde{s}_{g,t,i}^{(h*)} = m_g^{oof}(s_{g,t,i}^{(h_g)}, age_{t,i}, liquidity_{t,i}, regime_t)
```

其中：

- `m_g^{oof}` 只能用历史 OOF 样本训练
- 因变量统一为 `y^{(h*)}`，即 decision horizon 的未来超额收益
- `m_g` 可用单调回归、分桶校准、线性校准或 isotonic regression

因此，**L4 永远只对单一 decision horizon 的标签 `y^{(h*)}` 做回归**，不会直接混用多个 horizon 的标签。

如果某个家族的 native horizon 与 `h*` 相差过大，且 OOF 校准后仍不稳定，则不应硬塞进同一个 L4。更成熟的做法是：

- 将该家族留在独立 horizon sleeve 中
- 在更上层做 sleeve-level 组合
- 或者直接不纳入当前 decision horizon 的主模型

如果出于工程简化必须统一再平衡频率，推荐：

- 统一 decision horizon 为再平衡 horizon
- 只允许少数家族保留不同 native horizon
- 但必须先完成 OOF 的 horizon-consistent 校准
- 对快衰减因子在月频框架下从严准入

### 5.5 多频率因子的对齐原则

真实生产环境里，财务因子、价格因子、分析师因子和事件因子的更新频率并不一致。

推荐统一的 as-of 规则：

- **财务因子**：使用最近一次已披露值，并记录 `age_in_days`
- **日频价量因子**：在再平衡日收盘后按日更新
- **事件/预期因子**：按事件生效时间戳更新，并保留事件时效特征

对低频因子，不建议把“过时程度”直接乘到因子值上，因为衰减的是**信息置信度**，不是原始经济量本身。

更合理的做法是二选一或并行：

1. 把 `age/freshness` 作为额外特征输入模型
2. 把 freshness 作为**组内或组间的置信度权重**，而不是直接改写因子值

推荐默认形式：

```text
c_{g,t} = exp(-age_{g,t} / tau_g)
```

其中 `c_{g,t}` 只用于：

- 调节家族分数的置信度
- 进入 horizon calibration 模块
- 或作为 stack 的输入特征

而不是直接把 `x` 变成 `x * c`。

## 六、L1：因子预处理

这一步不是附属动作，而是弱因子能不能稳定叠加的前提。

### 6.1 推荐预处理顺序

在每个再平衡日 `t`，对横截面执行：

1. 去极值
2. 缺失处理
3. 截面标准化
4. 风格中性化
5. 稳定性变换

### 6.2 去极值

不推荐全局 clip；推荐按日截面做 robust winsor：

- `median ± 5 * MAD`
- 或者分位数截尾，如 `0.5% ~ 99.5%`

### 6.3 缺失处理

不同因子缺失含义不一样，不要统一 `fillna(0)`。

推荐做法：

- 会计类因子：行业内中位数填补
- 微观结构类因子：近期可得值前推或设缺失指示器
- 极度稀疏因子：单独降权或移除

如果后续上非线性模型，可以保留 `missing indicator`，但线性主模型不应依赖大量机械填零。

### 6.4 标准化

推荐两套并行表示：

1. **稳健 rank 表示**  
   `x_rank = rank(x)/(N+1) - 0.5`
2. **稳健 zscore 表示**  
   `x_z = (x - median) / (MAD + eps)`

通常在 A 股横截面里，rank 表示更稳，尤其适合多弱因子叠加。

### 6.5 风格中性化

每个再平衡日，对每个因子做横截面回归残差化：

```text
x_{t,:,k} = B_t * gamma_{t,k} + epsilon_{t,:,k}
```

推荐至少中性化这些暴露：

- 行业哑变量
- 对数流通市值
- beta
- 残差波动
- 流动性

如果策略目标是纯 alpha 合成，这一步非常关键。

实现上，推荐采用下面的明确规范：

- **对每个因子单独回归**，但回归右侧使用**同一组联合风险暴露**；不要按“先市值、再行业、再 beta”的顺序逐步回归，因为顺序会引入路径依赖。
- 默认使用**横截面 WLS**，权重可设为 `sqrt(float_mcap)` 后再 clip，避免极端大盘股主导；如果目标是更纯的小盘 alpha，也可以在 inner loop 中比较等权 OLS 与 WLS。
- 行业哑变量推荐使用“`K-1` 个行业 + 截距”或“`K` 个行业且无截距”两种等价写法之一，但必须全框架统一。
- 对样本极少的行业，建议使用行业合并、ridge 回归或行业内 shrinkage，避免回归矩阵近奇异。
- 如果 `B_t` 是**点时可得的截面暴露**（如行业、当日市值），则当日横截面残差化本身不需要额外做 OOF。
- 只有当 `B_t` 里包含**跨时间估计得到的暴露**（如 rolling beta、残差波动、历史协方差特征）时，这些暴露的估计窗口才必须严格因果、只使用历史数据。

### 6.6 不推荐的预处理方式

- 全样本 `zscore`
- 全样本分组均值填补
- 因子列直接 `fillna(0)`
- 先按全样本标准化，再滚动训练

## 七、L2：因子家族划分与冗余压缩

200 个弱因子并不是 200 个独立信息源。

更成熟的做法，是同时使用**经济家族划分**和**统计冗余压缩**。

### 7.1 推荐家族划分

建议至少拆成下面几类：

- 价值
- 质量
- 成长
- 动量
- 反转
- 波动与风险
- 流动性与换手
- 交易行为与微观结构
- 分析师预期与事件
- 另类数据

### 7.2 统计冗余处理

每个家族内部做下面几项检查：

- 截面相关矩阵
- rank IC 相关矩阵
- 换手相关矩阵
- 特征重要性稳定性

推荐规则：

- 同家族内相关性长期高于 `0.8` 的因子优先聚类压缩
- 大量共线因子先做 `PC1` 或 `ridge`，而不是全部保留独立权重
- 因子是否保留，优先看**增量 OOF 贡献**，不要只看单因子 IC

### 7.3 用有效维度替代名义因子数

建议监控：

```text
n_eff = (sum(lambda_j))^2 / sum(lambda_j^2)
```

其中 `lambda_j` 是家族内相关矩阵的特征值。

经验上：

- 名义 200 个因子，`n_eff` 可能只有 20～50
- 真正能解释样本外 alpha 的，通常更少

所以问题不是“保留 150 还是 200 个”，而是“保留多少**独立信息**”。

### 7.4 家族划分的稳定性与更新节奏

家族划分是整套分层结构的地基，因此不能在每次再平衡时频繁重构。

推荐规则：

- **经济分类优先**，统计聚类用于家族内压缩和边界复核
- 当经济分类与统计聚类冲突时，优先保留经济解释，再把统计异常项标记为 `review bucket`
- 家族定义只在**季度或半年级别**更新，不要日更或月更
- 家族定义更新后，旧家族和新家族之间要有映射表，便于历史回测和实盘监控衔接

同时建议做家族划分敏感性测试：

- 将边界因子随机扰动到相邻家族
- 比较最终 OOF 与组合表现的变化
- 评估“家族划分错误”对最终 alpha 的影响上限

### 7.5 因子准入、观察期与淘汰机制

收缩法会自然压低差因子的权重，但这不等于不需要准入/淘汰机制。

推荐采用三段式流程：

1. **候选池**：新因子先进入 shadow pool，不直接进入生产模型
2. **观察期**：按因子衰减速度决定最短 OOF 观察长度，验证增量贡献、稳定性和成本特征
3. **正式纳入/淘汰**：只有在 OOF 增量为正且稳健时纳入；若长期 OOF 贡献为零或为负，则从 active universe 中移除

建议与 5.4 的衰减分类对齐：

- **快衰减因子**：`6 ~ 12` 个月
- **中速因子**：`12 ~ 18` 个月
- **慢速因子**：`18 ~ 24` 个月

硬淘汰建议满足“持续失效”而不是单一窗口失效，例如：

- 连续 `4 ~ 6` 个评估窗口增量贡献为负
- 成本后贡献接近零
- 与现有因子高度共线且不提供增量解释力

## 八、L3：组内合成

### 8.1 组内合成的目标

组内合成的目标不是把所有因子都用上，而是生成一个对该家族更稳定的代表分数 `s_g`。

### 8.2 组内推荐方案

对每个家族 `g`，推荐并行计算三类子分数：

1. **稳健基线分数 `s_eq,g`**  
   家族内 rank 等权平均
2. **监督收缩分数 `s_ridge,g`**  
   用 rolling ridge 预测下期残差收益
3. **去冗余分数 `s_pc,g`**  
   取家族内 `PC1` 或前几主成分的稳定组合

然后在组内再做一次轻量叠加：

```text
s_g = stack_g(s_eq,g, s_ridge,g, s_pc,g)
```

这里的 `stack_g` 推荐用：

- ridge
- 非负 ridge
- 或简单固定权重，但权重必须由 OOF 结果决定

### 8.3 为什么不建议“组内风险平价”

因子波动大，不等于因子差；因子波动小，也不等于因子好。

组内权重应更多由下面三者共同决定：

- 预测强度
- 预测稳定性
- 与同组其他因子的冗余程度

因此，纯“因子波动率倒数加权”不是成熟的主方案。

### 8.4 PC1 的符号锚定与失稳处理

如果组内使用 `PC1`，必须显式处理方向不确定性问题。

推荐做法：

- 每个窗口计算出的 `PC1`，先与上一个窗口的 `PC1` 得分做相关性比较
- 若相关系数为负，则把当前 `PC1` 整体乘以 `-1`
- 在首个窗口，可用家族内等权基线 `s_eq,g` 作为方向锚；若 `corr(PC1, s_eq,g) < 0`，则翻号

如果出现下面情况，说明 `PC1` 不够稳定，应降权或停用：

- 第一特征值与第二特征值非常接近
- `PC1` 与上期 `PC1` 的相关性长期不稳定
- `PC1` 方向频繁翻转导致换手异常升高

当 `PC1` 不稳定时，推荐回退到：

- ridge 组内合成
- sparse PCA
- 或直接只保留 `equal-rank + ridge`

---

## 九、L4：组间收缩合成

这一步是整套方案的核心。

设经过组内合成后，得到 `G` 个家族分数：

```text
S_t = [s_1, s_2, ..., s_G]
```

### 9.1 默认主模型：Rolling Ridge / Elastic Net

默认主线建议使用更干净的正则形式：

```text
beta_t = argmin_beta  ||y^{(h*)} - \tilde{S} beta||^2
                        + lambda_ridge ||beta||_2^2
                        + lambda_lasso ||beta||_1
```

其中：

- `\tilde{S}` 是已经过 horizon-consistent 校准的历史 OOF 家族分数矩阵
- `y^{(h*)}` 是统一的 decision horizon 标签
- `lambda_ridge` 负责整体收缩，默认主正则
- `lambda_lasso` 只在确实需要更强稀疏性时启用

如果实现使用 `sklearn` 或 `glmnet` 风格参数化，建议在代码中显式映射为：

- `alpha_reg`：总正则强度
- `l1_ratio`：L1 占比

避免把参数名和范数阶数写反。

经验上：

- 家族数较少、强调平滑稳定时，用 **ridge**
- 家族数较多、确有淘汰需求时，用 **elastic net**

这比固定 `40/30/30` 成熟得多，因为它显式考虑了：

- 谁更有预测力
- 谁和别人更像
- 权重是否过于集中

### 9.2 协方差惩罚是可选增强，不是默认项

直接在原空间加入

```text
beta' Omega beta
```

并不是默认推荐，因为它有几个问题：

- 可能额外惩罚高方差但高信息量的方向
- 当 `Omega` 近似单位阵时，与 ridge 高度重叠
- 会引入额外超参数，提升 inner loop 复杂度

如果确实要做协方差感知收缩，推荐优先使用：

- 在 **PCA/whitened** 空间做 ridge
- 或对 `S` 先做正交化，再在正交空间里施加简单收缩

也就是说：

- **默认主模型**：ridge / elastic net
- **可选增强**：正交化空间下的 covariance-aware shrinkage

### 9.3 为什么收缩法是主线

高维弱信号环境下，最大的敌人不是欠拟合，而是“样本内看起来都有效，样本外一起失真”。

收缩法的优点：

- 对高相关信号更稳
- 对 OOS 更友好
- 对阈值不敏感
- 更容易与成本和风险模型联动

### 9.4 推荐输出形式

最终线性主分数：

```text
alpha_linear[t, i] = sum_g beta_{t,g} * s_g[t, i]
```

建议对 `beta_{t,g}` 加以下约束：

- 时间上平滑
- 权重上下界
- 非负或轻度允许负权
- 单家族上限

如果没有特别强的理由，不建议让家族权重频繁翻正翻负。

---

## 十、L5：非线性残差增强

### 10.1 非线性模型该放在哪里

更成熟的做法，不是让 GBDT/NN 直接吃全部原始因子并接管整个 alpha，而是：

1. 先用线性收缩主模型得到 `alpha_linear`
2. 再拟合残差：

```text
r_residual = y - alpha_linear
```

3. 用非线性模型只去解释 `r_residual`

最后：

```text
alpha_final = alpha_linear + eta * alpha_nonlinear
```

其中 `eta` 不是拍脑袋常数，而应视为 inner loop 中的受限超参数。

### 10.2 为什么这样更成熟

- 线性主模型提供可解释、可监控、可回退的核心 alpha
- 非线性模型只负责补充交互项和非线性边际效应
- 能明显降低过拟合和风格漂移风险

### 10.3 eta 的选择与统计检验

推荐把 `eta` 放进 inner loop 的小网格里，例如：

- `0`
- `0.05`
- `0.10`
- `0.20`
- `0.30`

其中 `eta=0` 必须永远保留，作为“关闭非线性 overlay”的合法选项。

只有满足下面条件时，才允许 `eta > 0`：

- 相比 `eta=0`，OOF 成本后 IR 或 rank IC 有稳定提升
- 提升在多数 outer folds 上方向一致，而不是只靠少数窗口
- bootstrap 置信区间或 block-bootstrap 检验支持增益为正
- 换手与容量恶化在可接受范围内

如果线性模型已经很好，而残差接近纯噪声，inner loop 应自然把 `eta` 选回 `0`。

### 10.4 非线性模型的使用边界

只有满足下面条件时，才建议让非线性增强进入生产：

- OOF 明显优于线性主模型
- 子样本稳定
- 特征重要性稳定
- 换手上升可接受
- 加成本后仍有增益

否则，宁可不用。

## 十一、L6：regime overlay 只能做软调节

成熟经验并不支持手工把市场切成“牛、熊、震荡”后，再做硬切换主模型。

更推荐的做法，是定义极少数**可实时观测**且低维的 regime 指标：

- 市场波动率
- 横截面收益离散度
- 横截面 alpha breadth
- 风格拥挤度
- 换手惩罚强弱

但默认生产实现不建议直接上“`5 个指标 × G 个家族` 的自由映射”，因为参数量会迅速膨胀。

默认建议分两步：

1. 先把 regime 指标压缩成 `1 ~ 2` 个稳定状态变量
2. 再用单调、低自由度的映射函数输出调节系数

例如：

```text
adj_t = clip(a + b * z_regime_t, lower, upper)
alpha'_t = adj_t * alpha_t
```

只有在充分验证后，才进一步升级到“分家族 overlay”。

生产默认建议：

- 先做**单一全局 aggressiveness multiplier**
- 映射函数用线性、logistic 或 3 桶 piecewise mapping
- 参数必须在 inner loop 中选择
- 上下界默认先用更窄的区间，例如 `0.9 ~ 1.1`

只有在样本外证据明确时，才放宽到 `0.75 ~ 1.25`。

也就是说：

- **可以软调节**
- **不要硬切换**
- **不要靠人工划历史阶段驱动主模型**

---

## 十二、L7：组合构建必须独立成层

这是原始版本最需要升级的地方之一。

### 12.1 因子合成层不直接输出仓位

正确流程是：

```text
原始因子 -> 合成 alpha -> 组合优化器 -> 权重
```

而不是：

```text
原始因子 -> 一个时间序列信号 -> 再硬套止损和杠杆
```

### 12.2 推荐组合优化目标

对每个再平衡日，解下面的问题：

```text
max_w   alpha_t' w
        - lambda_risk * w' Sigma_t w
        - lambda_tc_l1 * ||w - w_prev||_1
        - lambda_tc_l2 * ||w - w_prev||_2^2
        - lambda_hhi * ||w||_2^2
```

约束包括：

- 单票上限
- 行业偏离上限
- 风格偏离上限
- 总换手上限
- 净暴露 / 总暴露
- 流动性占比上限
- 不可交易股票权重冻结
- long-only 或 beta-neutral 约束

### 12.3 风险模型本身需要单独设计

`load_risk_model()` 不能是一个黑盒占位符。对生产级系统，风险模型至少要回答下面几件事：

- 用的是**基本面风险模型**、**统计风险模型**，还是混合模型
- 因子协方差矩阵如何估计、如何收缩
- 特质风险如何估计、如何设下限
- 风险模型更新频率是什么
- 是自建还是直接采购供应商模型

默认建议如下：

1. **若有成熟供应商模型**  
   对 A 股 long-only 或 benchmark-aware 任务，优先使用 Barra/CNE6 一类基本面风险模型作为生产主线。
2. **若自建风险模型**  
   推荐使用“行业 + 风格 + shrunk covariance + shrunk idio risk”的混合框架，而不是只用 PCA 统计模型。

自建风险模型的默认实现建议：

- **暴露层**：行业哑变量 + size + beta + residual vol + liquidity + momentum 等核心风格因子
- **因子收益**：用滚动横截面 WLS 估计
- **因子协方差**：EWMA 或 rolling window 估计后，再做 Ledoit-Wolf 或同类 shrinkage
- **特质风险**：对残差方差做 EWMA，并在行业/全市场层面再收缩，同时设置风险地板

更新频率建议：

- 暴露：每个再平衡日更新
- 协方差与 idio risk：周频或月频主更新，极端行情下可增量刷新

统计 PCA 风险模型可以作为补充监控或极端情况下的 fallback，但不建议作为 A 股生产主线的唯一风险模型。

### 12.4 因子中性化与优化器约束的关系

L1 的 alpha 中性化和 L7 的优化器约束不是重复控制，而是两道不同层次的防线：

- **L1 中性化**：尽量让 alpha 本身少带不想要的行业/风格暴露
- **L7 约束**：确保最终持仓在真实交易约束下仍然风险可控

成熟实现里，两者应满足下面关系：

- 在 **market-neutral** 策略中，如果中性化做得合理，优化器的行业/风格约束通常只应轻度 active；若长期强烈 active，说明 alpha 仍有明显暴露残留
- 在 **long-only** 策略中，精确零暴露通常不可实现，因此中性化更像“降偏”，优化器约束负责把主动偏离限制在可承受范围内
- 如果优化器约束长期高度绑定，不能只当成“优化器正常工作”，还要反查前面的 alpha 中性化和标签定义是否存在系统偏差

因此，生产监控里建议额外跟踪：

- 约束活跃次数
- 约束影子价格
- 优化前后 alpha 损失
- 中性化前后暴露变化

### 12.5 风险控制的正确落点

真正成熟的风险控制，应该体现在：

- 风险模型
- 成本模型
- 约束优化
- 交易分批执行

而不是在因子分数上直接做：

- 月内累计亏损减半
- 因子信号波动率越高就越减仓
- 看到回撤就硬砍 alpha

这类规则可以作为**组合层的应急开关**，但不能替代优化器。

## 十三、推荐的生产级默认方案

如果今天要在 A 股上生产一套成熟的弱因子合成框架，默认建议如下：

### 13.1 因子层

- 原始因子：100～500 个
- 再平衡频率：周频或月频
- 标签：下一期残差收益或 benchmark-relative return
- 标准化：按日截面 rank + robust zscore 双轨
- 中性化：行业 + ln(float mcap) + beta + residual vol + liquidity

### 13.2 合成层

- 家族数：6～12 个
- 组内：`equal-rank + ridge + PC1`
- 组间：rolling ridge / elastic net（默认）/ Bayesian shrinkage（可选）
- 非线性：仅做 residual overlay，权重受限
- regime：只做 soft gating

### 13.3 组合层

- 风险模型：优先供应商 Barra-style；若自建，则采用行业 + 风格 + shrunk covariance + shrunk idio risk
- 成本模型：显式 spread/slippage/impact/税费参数
- 优化：带换手惩罚的二次规划
- 约束：行业、风格、单票、流动性、换手、不可交易状态
- 协同原则：alpha 先做中性化降偏，优化器再做最终风险约束

### 13.4 基于当前真实 CSV 的第一阶段默认实验配置

对当前项目，建议不要一开始就上多 horizon、多 sleeve 或复杂 overlay。第一阶段 baseline 先固定成下面这套可执行配置：

- 数据源：`train_merged_all.csv`
- 资产键：`Unnamed: 0`，进入 pipeline 前统一重命名为 `stock_id`
- 时间键：`date`
- 标签：直接使用真实字段 `pchg`
- 因子池：当前 `260` 个因子全量纳入候选池
- 家族划分：先冻结 notebook 提供的 `9` 个家族分组
- decision horizon：先设为**单一一周期 horizon**，也就是当前周频面板上的 `1-bar pchg`
- 再平衡频率：周频
- L4：先做单 horizon 的组间 ridge / elastic net
- L5/L6：第一阶段默认关闭，等线性主线稳定后再逐步打开

对当前数据的 first trial，推荐 OOF/回测结构：

- 最小 outer 训练期：`260` 个周度样本
- outer test block：`52` 个周度样本
- inner validation block：`13` 个周度样本
- outer 推进步长：`4` 周
- embargo：先取 `1` 个周度样本
- final holdout：最后 `104` 个周度样本优先冻结

这套配置的目标不是一步到位，而是先在真实数据上拿到一条可信、因果一致、可复现的 baseline 曲线。

### 13.5 为什么这是主线

因为它在下面四件事之间平衡得最好：

- 样本外稳定性
- 可解释性
- 与交易成本的兼容性
- 后续扩展到 ML / IPCA / 另类数据的能力

## 十四、备选路线对比

| 路线 | 适合场景 | 优点 | 风险 | 建议 |
|------|---------|------|------|------|
| 纯 rank 等权 | 起步基线 | 极稳、易解释 | 利用率低 | 必做 baseline |
| 分层收缩合成 | 生产主线 | 稳、成熟、可扩展 | 研发量中等 | **默认推荐** |
| IPCA / latent factor | 研究增强 | 理论完整、能提炼低维结构 | 实现与监控更复杂 | 研究线强烈建议 |
| 全量 GBDT / NN | 模型探索 | 可抓交互 | OOS 和换手风险高 | 只做 overlay |
| 最近 IC top-k 激活 | 快速试验 | 直观 | 追噪声、抖动大 | 不建议做主线 |
| 因子风险平价 | 简单加权 | 算法简单 | 理论弱、易错配 | 不建议做主线 |

## 十五、什么时候考虑 IPCA

如果团队数据治理、回测引擎、矩阵计算和 OOS 评估都比较成熟，建议把下面这条线作为研究增强：

## **IPCA / Characteristics-Are-Covariances 路线**

它的优势在于：

- 不把每个因子都当成独立 alpha，而是把特征映射为**动态因子载荷**
- 能在低维 latent factor 空间里解释风险与收益
- 更适合处理大规模特征集和时间变动结构

它更像“统一的定价结构模型”，不是简单的加权器。

但它也有代价：

- 更难解释给业务和投委会
- 更难与交易成本和约束直接联动
- 对点时一致性和矩阵稳定性要求更高

因此更成熟的组织通常是：

- **生产主线**：分层收缩合成
- **研究增强线**：IPCA / latent factor

而不是一上来就完全押注 IPCA。

---

## 十六、样本外验证必须升级为嵌套式

弱因子合成最容易犯的错误，是：

- 先在全历史挑阈值
- 再在同一段历史上回测
- 最后把一小段尾部样本当作样本外

这不够。

### 16.1 Outer loop 的默认结构

标准 `k-fold` 不适用于时序资产定价问题，默认必须使用时间推进式 outer loop。

推荐默认配置：

- **月频框架**
  - 最小训练期：`60` 个月
  - outer test block：`12` 个月
  - 推进步长：`1` 个月
  - embargo：至少 `1` 个再平衡周期，若标签重叠则取不小于最大标签 horizon
- **周频框架**
  - 最小训练期：`156` 周
  - outer test block：`26 ~ 52` 周
  - 推进步长：`1 ~ 4` 周
  - embargo：至少 `1` 周，若使用多周重叠标签则相应放大

outer loop 的职责只有一个：模拟真实研究时点下的最终样本外表现。

### 16.2 Inner loop 的默认结构

inner loop 只在 outer-train 内部运行，用于选择超参数。

推荐原则：

- **慢因子和线性主模型**：优先 expanding window
- **快衰减因子和非线性 overlay**：优先 rolling window
- inner validation block 通常取 `6 ~ 12` 个再平衡周期
- inner step 通常取 `1` 个再平衡周期
- 超参数搜索优先用小网格或贝叶斯优化，但搜索空间必须事先收紧

所有这些参数都必须在 inner loop 决定：

- 家族划分版本
- 中性化暴露集合
- ridge/elastic net 收缩强度
- 非线性 overlay 权重
- 成本惩罚强度
- 组合约束松紧
- regime overlay 的开关与边界

### 16.3 OOF 的具体构造方式

本方案中，OOF 的含义是：

- 对每个 `(date, stock, horizon)`，预测值必须来自**不包含该样本及其泄漏邻域**的模型
- 每个样本最终只保留**一个**生产等价的 OOF 预测

推荐具体规则：

1. 先按时间把训练区间切成多个连续 validation blocks
2. 对每个 validation block，只用其之前的历史训练模型
3. 对 block 前后的样本执行 purge / embargo
4. 将各 block 的预测按时间拼接，形成完整 OOF 序列

不推荐做法：

- 标准随机 k-fold
- 对同一日期重复预测后再随意平均
- 不加 purge gap 直接相邻切块

如果标签窗口重叠，embargo 的下限建议为：

```text
embargo >= max(label_horizon, execution_delay, feature_publication_lag)
```

### 16.4 超参数跳变控制

当 inner loop 在相邻 outer windows 中选出的超参数剧烈跳动时，不能直接照单全收。

推荐增加稳定化机制：

- 只允许对**当前及历史 outer windows** 的超参数路径做单向稳定化，严禁使用未来窗口信息
- 对超参数路径做单向多数投票、递归平均或指数平滑
- 限制相邻窗口的参数变化幅度
- 优先选择表现接近最优但更稳定的参数
- 若多个参数组合统计上不可区分，选择更简单的那一个

也就是说，任何参数平滑都必须满足因果性：

```text
theta_t = f(theta_t^*, theta_{t-1}, theta_{t-2}, ...)
```

而不能使用 `theta_{t+1}` 或更远未来窗口的信息。

### 16.5 所有叠加器都必须使用 OOF 输入

无论是：

- 组内 stack
- 组间 stack
- 非线性 overlay
- regime 调节

其训练输入都必须是历史 OOF 预测，而不是样本内拟合值。

## 十七、评估指标不能只看 IC 和夏普

### 17.1 因子层指标

- rank IC
- ICIR
- partial rank IC
- 单调分组收益
- 增量解释力
- 稳定性与符号一致性

### 17.2 合成层指标

- OOF rank IC
- decile spread
- 信息比
- 因子家族权重稳定性
- 有效 breadth
- 信号自相关与换手

### 17.3 组合层指标

- 税费后 Sharpe / IR
- 最大回撤
- 月度胜率
- 换手率
- 容量
- 风险暴露偏离
- 成本占 alpha 比例

### 17.4 稳健性指标

- 不同年份表现
- 牛熊子样本表现
- 大小盘分层表现
- 行业分层表现
- 延迟执行 1 天后的表现
- 参数扰动后的表现
- 删掉最强 10% 因子后的表现

真正成熟的框架，必须“去掉一点优势后还能站住”。

### 17.5 统计检验与 data snooping 防控

如果研究团队会同时尝试很多种因子、标签和参数组合，单纯看最好的一条回测曲线没有意义。

推荐增加下面这些控制：

- block bootstrap 或 moving block bootstrap
- White's Reality Check / SPA 类方法
- 不同研究分支共享统一的最终样本外窗口
- 明确区分 `research OOS` 与 `final holdout`
- 禁止在 final holdout 上反复调参
- multiple testing 调整应发生在“模型家族选择”和“最终候选模型比较”两个节点

成熟框架的标准不是“有没有找到最好结果”，而是“最好的结果在严格控制试错次数后是否仍成立”。

推荐时间划分：

- `research OOS`：最后 `24 ~ 36` 个月
- `final holdout`：再往后的最后 `12 ~ 24` 个月，且在研究阶段完全冻结

如果样本本身不够长，宁可收缩研究自由度，也不要反复打开 final holdout。

## 十八、A 股场景下必须额外考虑

### 18.1 股票池与交易性

- 新股冷启动期
- ST / *ST
- 停牌
- 涨停买不到、跌停卖不出
- 一字板
- 流动性断层

### 18.2 成本与冲击

不要把成本只写成一个常数。

推荐至少分解成：

- 佣金
- 税费
- 双边或单边费用
- bid-ask spread
- 冲击成本
- 参与率惩罚

### 18.3 多频率因子的落地对齐

在同一个再平衡日，不同频率因子必须统一映射到同一 as-of 快照。

推荐规则：

- 低频因子使用最近已知值，并显式保留 `age/freshness`
- 高频因子使用最近一个完整 bar 或最近一个完整统计窗口
- 事件因子使用最近一次事件后可得的状态值
- 不允许把未来几天才发布的数据回填到当前再平衡日

如果低频因子在两次更新之间可能逐渐失效，建议加入 freshness decay：

```text
c_{g,t} = exp(-age_{g,t} / tau_g)
```

但这里的 `c_{g,t}` 代表**信息可靠性权重**，不建议直接乘在原始因子值上。

推荐把它用于：

- 组内/组间分数的置信度调节
- horizon calibration 的附加输入
- 或作为单独 freshness feature

并通过 inner loop 比较“无 freshness 处理”和“有限 freshness 处理”两种版本。

### 18.4 财务因子时滞

季度、半年报、年报因子都必须使用：

- 实际披露日期
- 保守生效延迟
- 修正公告后的回填规则

财务因子时点错一层，整套回测都可能被高估。

### 18.5 容量与拥挤

弱因子合成很容易在中小盘和低流动性标的上看起来特别漂亮，因此必须显式评估容量：

- 单票成交额占比上限
- 组合整体 ADV 占比
- 资金规模放大后的 alpha 衰减
- 风格拥挤代理变量
- 同类策略挤兑下的成交可得性

如果一个方案只有在很小资金量、很低参与率下才成立，它仍然可以是研究成果，但还不能算成熟的生产方案。

### 18.6 long-only 与 market-neutral 需要不同设计

同样一套弱因子合成，在不同组合目标下，落地方式应该不同：

- **long-only**：更关注 benchmark-relative alpha、行业和风格主动偏离、容量与跟踪误差
- **market-neutral**：更关注 beta 中性、行业中性、融资融券可得性、借券成本和净暴露稳定

也就是说，因子合成本身可以共用，但标签、中性化方式、优化器约束和评估指标不能完全共用。

### 18.7 存活偏差与退市收益处理

点时一致性不只是“股票池用当时成分”，还包括显式处理退市样本。

必须明确：

- 训练和测试截面中是否包含后来退市的股票
- 退市前最后一段收益是否完整计入
- 退市整理期、暂停上市、重新上市如何映射
- 数据供应商是否真的提供了退市股票的历史因子与价格

如果退市样本被静默丢弃，A 股横截面回测通常会被系统性高估。

## 十九、不建议再采用的设计

下面这些做法可以作为实验，但不建议再作为主方案写进生产级技术文档：

1. **全样本标准化**
2. **直接按近期 IC 排名激活 top-k 因子**
3. **手工划牛熊阶段并硬切主模型**
4. **固定 `40/30/30` 三路融合**
5. **因子波动率倒数作为核心权重**
6. **把因子合成输出直接当仓位**
7. **在因子层做止损和杠杆控制**
8. **只看样本内夏普、只留 1～2 年尾部样本外**

这些设计最大的问题，不是“完全没用”，而是**不够成熟，且容易把研究导向过拟合**。

---

## 二十、推荐落地顺序

虽然本文件定义的是终极方案，但真正上线时，建议按下面顺序实现：

### Phase 1：生产主线

- 点时数据治理
- 预处理
- 家族划分
- 组内合成
- 组间收缩合成
- 成本感知优化器

### Phase 2：研究增强

- OOF stacking 改进
- regime soft gating
- 残差 GBDT overlay
- 容量模型增强

### Phase 3：结构升级

- IPCA / latent factor
- 统一 alpha-risk 联合估计
- 多目标优化

这样做不是保守，而是为了让最终的“终极方案”具备真正可生产的稳定性。

### 工程与算力架构

“可生产”不仅是研究逻辑正确，还包括工程上可持续运行。

推荐至少满足下面几点：

- 因子面板、风险暴露、标签和成本数据分层缓存
- 增量计算优先于全量重算
- OOF 结果、inner loop 结果、outer loop 结果分别落盘
- 对大矩阵计算采用列式存储、分块读取和并行化
- 为每个研究版本保留参数快照、数据版本和随机种子

对于 `500` 因子 × `4000+` 股票 × 嵌套 CV 的场景，若没有缓存和增量管线，研究吞吐会明显不足。

### 上线闸门

建议为生产上线设置硬性 gate：

1. 税费后结果成立
2. 延迟执行后结果仍成立
3. 容量测试不过度衰减
4. 风险暴露可解释且可控
5. 参数扰动后不脆弱
6. final holdout 不弱于 research OOS 的可接受区间

只要其中一项明显不过关，就不应因为“样本内很漂亮”而强行上线。

### 实盘监控

上线后也不能只盯 PnL，建议持续监控：

- 因子家族权重漂移
- OOF 预期与 realized alpha 偏差
- 换手与成本偏离
- 风格暴露漂移
- 交易失败率与不可交易率
- 分层 decile spread 是否塌陷

成熟方案的标志之一，不是从不失效，而是失效时能快速定位是在数据、模型、优化器还是执行层出了问题。

for outer_train, outer_test in outer_walk_forward_splits(schedule, embargo=embargo):

    for rebalance_date in outer_test:

        tradable = get_tradability_mask(rebalance_date, universe)

        # L1: preprocess at as-of date
        X_raw = load_factor_panel(rebalance_date, universe)
        X_clean = winsorize_and_impute(X_raw)
        X_std = cross_sectional_standardize(X_clean)
        X_neu = neutralize_against_risk_exposures(X_std, rebalance_date)

        # L2: taxonomy / redundancy
        families = apply_frozen_family_map(X_neu, model_state.family_map)

        # L3: intra-family scores
        family_scores = {}
        for g in families:
            s_eq = family_equal_rank_score(g)
            s_ridge = predict_family_ridge_oof(model_state, g, X_neu)
            s_pc = family_pc_score_with_sign_anchor(model_state, g, X_neu)
            family_scores[g] = stack_family_scores_oof(
                model_state, g, s_eq, s_ridge, s_pc
            )

        # L4: linear alpha
        alpha_linear = predict_cross_family_model(model_state, family_scores)

        # L5: nonlinear residual overlay
        alpha_nl = predict_residual_overlay(model_state, X_neu)
        alpha = alpha_linear + model_state.eta * alpha_nl

        # L6: soft regime overlay
        alpha = apply_soft_regime_adjustment(alpha, rebalance_date, model_state.regime_map)

        # L7: optimizer
        risk_model = load_risk_model(rebalance_date, universe)
        cost_model = load_cost_model(rebalance_date, universe)

            alpha=alpha,
            risk_model=risk_model,
            cost_model=cost_model,
            tradable=tradable,
            prev_weights=prev_weights,
            constraints=model_state.constraints,
        )

        store_oof_prediction(rebalance_date, alpha)
        execute(weights)
        prev_weights = weights

`fit_pipeline()` 内部不应是黑盒，而应遵循严格的因果顺序：

```python
def fit_pipeline(train_range, config):
    # 0. freeze decision horizon h*
    y_decision = build_label(train_range, horizon=config.decision_horizon)

    # 1. build family map and preprocessing recipe
    family_map = fit_family_map(train_range, config)
    preprocess_state = fit_preprocess_recipe(train_range, config)

    # 2. intra-family native OOF
    native_family_oof = {}
    for g in family_map:
        s_eq_oof = build_family_equal_score_oof(train_range, g, preprocess_state)
        s_ridge_oof = build_family_ridge_score_oof(train_range, g, preprocess_state)
        s_pc_oof = build_family_pc_score_oof(train_range, g, preprocess_state)
        native_family_oof[g] = stack_family_scores_oof(
            s_eq_oof, s_ridge_oof, s_pc_oof, config
        )

    # 3. horizon calibration: native horizon -> decision horizon
    calibrated_family_oof = {}
    for g, s_native_oof in native_family_oof.items():
        calibrated_family_oof[g] = calibrate_to_decision_horizon_oof(
            s_native_oof, y_decision, config
        )

    # 4. cross-family linear OOF
    alpha_linear_oof = build_cross_family_model_oof(
        calibrated_family_oof, y_decision, config
    )

    # 5. residual overlay OOF
    residual_oof = y_decision - alpha_linear_oof
    alpha_nl_oof = build_residual_overlay_oof(
        train_range, residual_oof, preprocess_state, config
    )

    # 6. decide eta / regime / constraints using only OOF results
    final_state = refit_all_components_on_full_train(
        train_range=train_range,
        family_map=family_map,
        preprocess_state=preprocess_state,
        config=config,
    )
    return final_state
```

换句话说，组内模型、horizon calibration、组间线性模型和残差 overlay 之间是**严格串行因果链**，不能被实现成随意并行的模块。

## 二十二、对预期收益的正确预期

成熟方案不应该先写“夏普一定大于多少”，而应该先写：

- 哪些环节最容易产生高估
- 哪些改动最可能让样本外下降
- 哪些收益是结构性、哪些收益是偶然的

更稳妥的表述是：

1. 如果点时数据、成本、交易性处理不严格，任何漂亮结果都不可信。
2. 如果因子之间高度共线而未收缩，样本外通常会明显衰减。
3. 如果组合优化忽略换手和容量，收益大概率高估。
4. 如果非线性模型没有 OOF 和子样本验证，超额收益大概率不可持续。

也就是说：

- 先追求**结构正确**
- 再追求**样本外稳定**
- 最后才追求**更高夏普**

## 二十三、本方案相对旧版的核心升级

相对旧版，v2 的关键变化是：

1. **把因子合成和组合构建彻底分层**
2. **用分层收缩代替简单三路拍权重**
3. **用 OOF stacking 代替样本内权重选择**
4. **用成本感知优化器代替因子层止损**
5. **用 soft regime 代替手工硬切牛熊阶段**
6. **把 IPCA / latent factor 作为研究增强路线纳入体系**
7. **把 A 股点时一致性、交易约束和财务时滞提升为一等公民**

## 二十四、最终结论

对 A 股股票弱因子合成来说，**最成熟、最值得作为默认主线的设计**不是“等权 + 风险平价 + ML 三路融合”，而是：

## **分层收缩合成 + OOF 叠加 + 成本感知组合优化**

原因很简单：

- 它最符合高维弱信号问题的本质
- 它最能处理因子冗余和样本外衰减
- 它最容易和真实交易约束对齐
- 它也最方便未来接入 IPCA、非线性 overlay 和另类数据

如果只能记住一句话，那就是：

## **弱因子合成的主战场不在“更复杂的模型”，而在“更正确的层次划分、收缩估计、点时数据和成本约束”。**
