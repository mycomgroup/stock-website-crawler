## 组合与风控树核心理念

研究树解决的是"选什么"，组合树解决的是"怎么拿"。

很多研究在选股上没问题，但最后输在：

- **仓位**：持有几只？等权还是加权？仓位如何分配？
- **调仓频率**：每周调还是每月调？满足条件立刻换，还是固定时间换？
- **风险控制**：如何过滤风险股？如何控制回撤？
- **风格暴露**：是否过度集中在一个行业？是否过度集中在一个风格？

你的任务是通过回测结果，找到最优的组合管理参数配置。

## I树的五个分支

### I1. 股票池构建

先决定你研究哪一类：

- 全市场
- 大盘股
- 中小盘
- 红利
- 机构重仓
- 高增长

**自然语言条件样例（参考）：**

```
股票池一：非ST，非退市，流通市值大于20亿元，最近一年净利润为正

股票池二：非ST，中小市值，营业收入同比增长率大于20%

股票池三：非ST，高股息，经营现金流量净额为正
```

### I2. 排名与打分

单条件选股之后，通常还需要排序。

排序可以用：

- 估值从低到高
- 增长从高到低
- 资金流入从高到低
- 综合打分

**自然语言条件样例（参考）：**

```
满足条件后按市盈率从低到高排序

满足条件后按净利润同比增长率从高到低排序

满足条件后按主力资金流向/流通市值从大到小排序
```

### I3. 持仓与调仓

你必须研究：

- 持有几只
- 等权还是加权
- 每周调还是每月调
- 满足条件立刻换，还是固定时间换

**自然语言条件样例（参考）：**

```
持股数量5只，每20个交易日调仓一次

持股数量10只，每周一开盘后调仓

满足买入条件后按排名买入前3只，不满足条件即卖出
```

### I4. 风险过滤

无论哪棵树，都建议先建立统一排雷层：

- 非ST
- 非退市风险
- 非长期停牌
- 最低流动性要求
- 最低市值要求
- 重大减持或财务异常过滤

**自然语言条件样例（参考）：**

```
非ST，非退市，非停牌，流通市值大于5亿元，近1个月有减持公告取反

非ST，最近20日日均成交额大于3000万元，资产负债率小于80%

非ST，非重大财务造假风险，经营现金流量净额不连续两年为负
```

### I5. 组合层面管理

你需要研究的不是一只股，而是整个组合：

- 是否过度集中在一个行业
- 是否过度集中在一个风格
- 是否过度集中在单一催化
- 是否容易在同一种市场里同时失效

**自然语言条件样例（参考）：**

```
单一行业持仓不超过30%，单只股票仓位不超过20%

价值类与成长类各占一半，事件驱动类不超过组合的20%

高股息、防守型、成长型三类策略同时持有，并按月再平衡
```

### 第 3 步：分析历史，选择变异方向

读取或创建 `search_notes.md`，维护搜索地图：

### 待探索方向
（列出基于回测结果观察到的潜在改进方向）

### I树分支探索记录
- I1分支（股票池构建）：尝试过哪些，结果如何
- I2分支（排名与打分）：尝试过哪些，结果如何
- I3分支（持仓与调仓）：尝试过哪些，结果如何
- I4分支（风险过滤）：尝试过哪些，结果如何
- I5分支（组合层面管理）：尝试过哪些，结果如何

**决策规则：**
1. 优先从回测结果中观察到的问题出发（如回撤太大、持仓过于集中等）
2. 根据当前formula判断处于哪个分支，尝试深化该分支或切换分支
3. 不要重复"已验证无效"的方向
4. 每次变异要能解释"为什么这样改"

---

### 第 4 步：执行迭代

```bash
SKILL_DIR="skills/autoresearch_10jqka_backtest"
python ${SKILL_DIR}/run_iteration.py \
    --base trees/I_portfolio_risk/experiments/<name> \
    --mutation-summary "【变异类型】具体改了什么（改前→改后），预期效果" \
    [--mutation-type <type>]
echo "exit: $?"
```

`--mutation-summary` 格式要求：
- 写清楚**变异类型**
- 写清楚**具体改了什么**
- 写清楚**预期效果**

`--mutation-type` 可选，不指定时系统随机选择变异类型。

**退出码含义：**
- `0` = keep（新配置更优，已保存为 champion）
- `1` = rollback（新配置不如 champion，已恢复）
- `2` = crash（执行出错，consecutive_failures +1）

## 回测参数探索

组合与风控策略的特点：

- **持仓周期**：可探索不同周期，如 5天、10天、20天
- **持仓数量**：**8-15支最佳**，分散风险同时保持收益
- **止盈**：适中，可探索 12-20%
- **止损**：适中，可探索 6-10%
- **移动止损**：重要参数，可探索 3-8%

根据回测结果调整：
- 如果回撤太大 → 加强风险过滤条件或调整止损/移动止损
- 如果换手太频繁 → 增加 daysForSaleStrategy 或调整筛选条件
- 如果持仓过于集中 → 增加 maxPositions 或放宽筛选条件
- 如果选股太少 → 放宽筛选条件

## 每次迭代要回答的标准问题

在每次变异前，问自己这几个问题：

### 逻辑问题
- 这个改动改善的是仓位管理、调仓频率，还是风险控制？
- 这个逻辑依赖什么市场前提？

### 因子问题
- 主因子是什么？辅因子是什么？
- 风险过滤条件是否充足？

### 市场环境问题
- 牛市更有效还是熊市更有效？
- 流动性收缩时是否失效？

### 风险问题
- 最大回撤可能来自什么？
- 是否存在行业集中风险？
- 是否存在风格暴露风险？

## 组合与风控树研究常见错误（避坑）

1. **没有建立排雷层** - 先过滤ST、退市、减持公告等风险
2. **持仓过于集中** - 单一行业或风格暴露过大
3. **换手过于频繁** - 交易成本侵蚀收益
4. **忽视流动性** - 选入流动性差的股票导致滑点
5. **忽视风格暴露** - 在某种市场环境下全军覆没

## 评分公式（v2 - 防过拟合优化版）

```
calmar = annual_return / max(abs(max_drawdown), 0.01)
complexity_penalty = min((formula条件数 + 调优参数数) / 10, 1.0)

# 选股数量惩罚（双边软约束）
if maxPositions < 5:
    position_penalty = (5 - maxPositions) ** 2 * 0.1  # 选1支扣1.6分
elif maxPositions > 15:
    position_penalty = (maxPositions - 15) ** 2 * 0.01  # 选50支扣1.2分
else:
    position_penalty = 0

score = sortino * 0.40 + calmar * 0.25 + information_ratio * 0.15 
      + win_rate * 0.10 - complexity_penalty * 0.10 - position_penalty
```

**选股数量建议**：8-15支最佳，分散风险同时保持收益。

**硬约束**：
- `abs(max_drawdown) > 0.35` 直接 rollback
- 新 score **严格大于** champion score 才 keep

## 简洁性原则

改动要权衡收益和复杂度：
- 微小提升（score 提升 < 0.001）但增加了大量复杂配置 → **不值得**
- 删掉筛选条件后得分持平或更好 → **一定 keep**
- 得分接近但配置更简洁 → **keep**
