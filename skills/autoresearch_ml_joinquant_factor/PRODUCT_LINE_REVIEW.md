# 产品线化评审（autoresearch_ml_joinquant_factor）

## 已具备
- 独立初始化入口（`setup.py`）
- 独立执行器（`notebook_executor.py`）
- 基线配置与说明文档

## 仍需解决的问题（产品线视角）

### P0（上线阻断）
1. **数据契约未固化**
   - 未定义 JoinQuant 返回字段的 schema 与缺失值协议。
2. **可复现性不足**
   - 未统一随机种子策略（模型、采样、并行执行）。
3. **实验注册缺失**
   - 尚无全局 experiment registry（实验ID、版本、参数、产物）。

### P1（稳定性）
1. **故障隔离不足**
   - 单次执行失败仅在 stdout/stderr 体现，缺乏分级错误码。
2. **回测与实盘配置未分离**
   - 需要 profile：research/staging/prod。
3. **成本模型仍简化**
   - 仅 bps 惩罚，缺少冲击成本（与成交额、流动性联动）。

### P2（效率与治理）
1. **无自动化测试矩阵**（单测/回归/OOS快照）
2. **无性能基线**（执行时长、API调用量、内存）
3. **无发布规范**（版本号、变更日志、迁移说明）

## 建议路线图
- M1：补数据契约 + 错误码 + registry
- M2：补 profile 配置 + 可复现机制 + 回归测试
- M3：补监控（运行耗时、异常率、收益漂移）+ 发布流程
